# Complete Runtime Acceptance

Day 35 proves that the exact healthy Day 34 preview works through its complete locked end-user
contract in real Chromium. The generic runtime fixture is verification data; no official ASCOS
product pilot is selected.

## Exact persisted sources

`CompleteRuntimeAcceptanceService` independently reloads the Day 34 preview artifact, the immutable
managed-product runtime-configuration revision, and the immutable declarative browser plan. The
work order and current founder-issued authority bind their digests plus tenant, opportunity,
product, repository, isolated feature branch, commit/tree, preview environment/origin/deployment,
acceptance run, locked profile identity/version/digest, ordered capability/journey IDs,
authentication journey, and sorted opaque login-reference IDs.

The preview must still be active, healthy, preview-only, current, and bound to the exact deployed
commit/tree. Its production, merge, release, billing, secret, unapproved-network, and general-command
counts remain zero. The runtime configuration targets that same preview origin and source. The
browser plan must match the configuration, commit, profile, ordered journeys, and login references
byte for byte. Drift or missing persistence fails before a browser opens.

## Closed Chromium execution

The controlled provider resolves only the plan's opaque secret references and invokes one approved
managed-browser provider once. No raw credential is accepted by Day 35 models or persistence. Values
exist only in bounded in-memory input and redaction buffers, are masked in screenshots, and are
cleared immediately after invocation.

Every locked module journey must return PASS with browser-step, console, network, and exactly one
screenshot evidence record bound to the exact run, plan, and commit. The declared authentication
journey is mandatory. Missing, duplicate, undeclared, stale, failed, console-error, network-failure,
or screenshot-incomplete evidence fails closed and cannot create a passing terminal artifact.

## Persistence and retries

On success, a canonical mode-0600 write-once artifact records the complete Day
26/27/28/30/31/32/33/34 source chain, exact runtime configuration/profile/plan/browser-execution
digests, ordered journey receipts, one browser launch, one authenticated session per journey, one screenshot per
journey, and empty prohibited-effect counts. It stores no local path, raw secret, cookie, token,
authorization header, or provider payload.

Exact retry and restart reopen the same artifact without resolving credentials or launching another
browser. Changed retry state conflicts. Unknown fields/entries, path escape, unsafe permissions,
symlinks, non-canonical content, identity drift, and tampering are rejected.

## Stop boundary

Day 35 does not change or delete the preview, write product or ASCOS repositories, approve or merge
a pull request, deploy or promote production, execute rollback, release, bill, spend budget, accept
risk, make subjective founder UX decisions, or select an official pilot. The first end-to-end
product pilot remains separately authorized Day 36.
