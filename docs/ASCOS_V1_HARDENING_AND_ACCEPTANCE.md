3. explicit recovery drill verified;
4. tamper-evident audit chain verified;
5. five operational monitoring signals healthy;

Each receipt binds its exact control digest and the previous audit digest. A missing, reordered,
duplicate, fabricated, unhealthy, or malformed receipt prevents terminal evidence.

## Backup and recovery runbook

The Day 37 store writes one canonical primary artifact and one byte-identical backup as regular
mode-0600 files beneath a tenant/execution-contained directory. Strict reads require both copies,
verify their canonical envelopes and record digests, and require exact artifact equality. Unknown
entries, symlinks, unsafe permissions, path escape, identity drift, or disagreement fail closed.

Recovery is explicit, never silent. An operator first validates the backup independently, then may
replace only a missing or corrupt regular primary. The restored primary is reread through the full
strict path and must equal the original typed artifact. A bad or ambiguous backup stops recovery.

## Monitoring and audit runbook

The locked signal set is runtime health, persistence integrity, outbox backlog, worker liveness,
and browser-journey health. Every signal must be `HEALTHY` with a source-bound evidence digest.
Operators must continue to monitor real deployments separately; Day 37 creates no production
monitoring connection.

Seven control receipts form a single ordered hash chain beginning with the all-zero genesis digest.
The artifact envelope and duplicated canonical copy make later mutation detectable. Audit evidence
contains no credential, raw provider response, customer free text, command output, or host path.
